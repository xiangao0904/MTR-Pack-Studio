> below is historical; binary regression fixtures now live in `tests/fixtures/preview-glb/`.

Status recorded on 2026-09-22. The editor and automated export checks are available;
visual acceptance inside Minecraft remains pending. See
[export-compatibility.md](export-compatibility.md) for the pinned MTR contracts and
the game profiles checked on this machine.

## User workflows

1. **Build a carriage.** Create or open a project, choose **Trains**, create a train
   and select a carriage. In **Models & Textures**, import a body and front/rear bogies.
   Multiple layers can be added, renamed, replaced, hidden or removed. Configure
   carriage dimensions, bogie positions and coupling gaps in its properties.
2. **Edit materials and parts.** Select a model layer to inspect its individual
   materials. **Replace texture** changes one binding; **Reset** restores the
   imported texture. **UV Flip** updates that layer's preview. Pick a part in the
   viewport or model tree to synchronize selection and edit its placement
   override. Grid, direction and dimension guides help check positioning.
3. **Preview a consist.** Switch from **Single carriage** to **Preview consist**.
   Add the selected carriage repeatedly, drag instances into order, reverse an
   instance or remove it. **Simulate placement** applies carriage and part rules
   to the preview. This editor arrangement is independent of exported game train
   configurations.
4. **Save and reopen.** Fields save after an 800 ms pause; structural changes save
   immediately. **Ctrl+S** flushes pending work. Returning home, switching projects,
   exporting and closing the desktop window wait for pending saves. A failure
   retains the active editor so the user can retry. Reopen the `.mtrpack` file to
   inspect retained models, bindings, rules, thumbnails and consist settings.
5. **Set a project image.** Open **Project Settings → Upload image** and choose PNG,
   JPEG or WebP. The image is stored in the project and shown in recent projects
   and the workspace. **Use default image** restores the shared train SVG.
   Namespace and description use the same guarded save workflow.
6. **Browse future content.** **Eye candy** replaces the former decorative objects
   label and has a visible tree icon in both sidebar and content cards. It remains
   marked **Planned**; this iteration implements train editing.
7. **Export.** Choose **Export Pack**, then select MTR 4 or MTR 3 + NTE and a
   Minecraft version. MTR 4 also offers OBJ or MQO. Validation errors identify the
   train, carriage, layer or field and can take the user to the relevant editor.
   Resolve errors before choosing the ZIP destination.

## Original sample and generated artifacts

The original source fixture is in
[`src-tauri/tests/fixtures/studio-train/`](../src-tauri/tests/fixtures/studio-train/).
Its README describes geometry, materials and regeneration. Import `body.obj`
with its adjacent MTL/PNG files, then import `bogie.obj` into both bogie slots at
`7` and `-7` metres. The body has two textured materials, separately named doors
and windows, and an asymmetric texture stripe for checking vertical UV flipping.

Run from `src-tauri`:

```text
cargo test --locked
```

The test `authored_train_round_trips_and_exports_all_three_formats` imports the
source files, checks resource reuse and embedded preview textures, saves and
moves the project, reopens it, and exports all three formats. It leaves these
reviewable outputs under `src-tauri/target/acceptance/`:

| Artifact | How to use it |
| --- | --- |
| `Studio Acceptance.mtrpack` | Open in the desktop app; edit **Studio Metro**, whose body and two bogies are already imported. Its three-instance preview ends with a reversed carriage. |
| `mtr4-obj.zip` | Load as a resource pack in Minecraft 1.20.4 with MTR 4.0.5; inspect the OBJ export. |
| `mtr4-mqo.zip` | Load in the same MTR 4 environment to compare the MQO export. |
| `mtr3-nte.zip` | Load in Minecraft 1.20.1 with MTR 3 and NTE; the sample uses the `sp1900` base train. |

These outputs are generated test artifacts and can be regenerated by rerunning
the test. Copy the project before making acceptance edits that need to survive
another run. Enable one sample ZIP at a time to avoid resource ID collisions.

For browser UI checks, the public `/fixtures/studio-train.glb` and
`/fixtures/studio-bogie.glb` previews use matching part and material IDs. Browser
model import loads these built-in samples and displays a notice. Importing a
user's model files and producing real resource-pack ZIPs require the desktop app.

## Recorded browser checks

- Imported the textured sample body and both bogies; reopening retained all three
  layers and 552 triangles. The **Paint** and **Glass** materials were displayed.
- A thumbnail was generated from the actual viewport and persisted across reopen.
- Selecting **Body_Shell** in the tree synchronized the selected model part.
  Part rule inheritance and enabling an override were exercised.
- Applying **Last** hid the body on the first carriage during placement simulation.
- Repeated and reversed consist instances were saved. Editing a train name and
  immediately returning from the editor retained the new name.
- Default train artwork was visually checked in the workspace and settings.
- The **Eye candy** tree icon and label were visible without icon shrinkage.
- In the **Artwork Acceptance** browser project, changing the description and
  immediately navigating to **Overview** showed the saved new description.
- Reopening that project retained the description, and the settings page showed
  the editable project image, namespace and description controls.

The verification run also passed 24 native Rust tests, 5 frontend tests,
`pnpm build`, and `tauri build --debug --no-bundle`. These results cover the editor,
storage and export contracts exercised by those checks. They do not constitute a
game visual acceptance run.

## Recorded Windows desktop checks

The built Windows application opened `Studio Acceptance.mtrpack` through the
system file dialog. Its embedded body textures, both bogies, generated thumbnail,
and three-instance consist (including the reversed last carriage) rendered in
the native WebView. Replacing the body through **Replace model** with the original
`body.obj` resolved its adjacent MTL/PNG dependencies and retained three layers
and 552 triangles. The workspace returned to **Saved**.

Both export targets were exercised through the desktop export dialog:

- `Studio Acceptance MTR4.zip`: 30 entries.
- `Studio Acceptance MTR3-NTE.zip`: 10 entries.

Each archive passed ZIP integrity checking and matched every entry and payload
of the corresponding automated export. These files are in
`src-tauri/target/acceptance/` and remain separate from the test-generated ZIPs.

Uploading `public/fixtures/checker.png` in project settings updated the settings
preview and sidebar, then remained visible in recent projects after returning
home. A copy of that saved project, including its native thumbnail and uploaded
cover, is retained as `src-tauri/target/acceptance/Desktop Acceptance.mtrpack`.
The close-flow check exposed a missing Tauri `allow-destroy` permission. The
permission and asynchronous close handler were corrected so a successful flush
lets the SDK destroy the window, while a failed flush prevents closing.
The corrected Windows executable built successfully. The follow-up close test
was interrupted when the user pressed Escape to stop desktop automation; the
corrected close behavior still needs a final manual check.

## Remaining game acceptance

No in-game visual acceptance is recorded. Use the generated ZIPs in the matching
game profiles to check readable texture orientation, forward direction, metre
scale, bogie spacing, all model layers and material colors. Compare MTR 4 OBJ and
MQO visually. In MTR 3 + NTE, additionally exercise first/last, periodic and custom
placement rules with several train lengths. Confirm that changing the editor's
preview order leaves exported resource definitions unchanged.
